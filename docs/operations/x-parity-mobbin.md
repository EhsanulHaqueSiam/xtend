# X parity: finding X's own flows on Mobbin

Mobbin recorded X's web app as 167 named flows in 23 sections: https://mobbin.com/apps/x-web-40d9ec6f-9b08-4429-a30c-4d3e926218bd. Before building or checking an X flow in Xtend, look at how X does it there. This page is the index: grep it for the flow, then make one call.

## One lookup

1. Find the flow below (`rg -i "reply" docs/operations/x-parity-mobbin.md`).
2. It has a link: that is X's recorded flow. Cite it; search by name only when you need its screens in front of you.
3. Every flow has its link. A row with no line on what X does yet: one call, then add that line.
   Mobbin recorded no Translate, voting in a poll, Followers lists, the profile bell or the Block dialog; check those on the live account through the engine. When Mobbin adds flows, the app's Flows page, signed in, lists every flow's id and name in its page data.
   - A whole flow: `mcp__mobbin__search_flows` with `platform: "web"`, `query: "X <Flow>"` (the exact name from the table, e.g. `X Sorting replies`), `limit: 1`. The result's `id` is the link: `https://mobbin.com/flows/<id>`.
   - One state inside a flow (a menu, a dialog, a toast, an empty state): `mcp__mobbin__search_screens` with `platform: "web"`, `query: "X <what is on screen>"` (e.g. `X post more menu`), default `deep` mode, `limit: 2`. Its link is `https://mobbin.com/screens/<id>`.
   - Skip `search_sections`: it holds marketing website sections, not X's app.

Every result inlines preview images at 1 to 2K tokens each, so keep `limit` low. For many flows at once, run the calls in a subagent that returns text only (flow, link, what each step shows). When MCP tools are deferred, load them first with ToolSearch `select:mcp__mobbin__search_flows,mcp__mobbin__search_screens`.
